Re-verified both directions (missing var → exit code 1, no "Ready" state; all vars present → starts normally, `/api/health` responds) against the real standalone server.

### Fixed — M4.3: Accessibility Audit (see ACCESSIBILITY_REPORT.md for full detail)
- **`components/test-engine/TimerAnnouncement.tsx` (new):** both `CountdownTimer.tsx` and `WritingEngine.tsx`'s inline timer had `aria-live="polite"` on a value that changed every second — effectively unusable for screen reader users (either spammed constantly or silently dropped by AT throttling). Replaced with a visually-hidden announcer that fires only at meaningful milestones (5 min/1 min/30s/10s/time's up), via crossed-threshold comparison so it can't miss a boundary.
- **`TestEngine.tsx` + `WritingEngine.tsx`:** both had a hand-rolled `<div role="alertdialog" aria-modal="true">` submit-confirmation with none of the behavior `aria-modal` implies (no focus trap, no Escape handling, no focus return) — claiming modal semantics without providing them. Replaced both with the existing `components/ui/ConfirmDialog.tsx` (native `<dialog>`, from M3.1), which provides real focus containment/Escape/backdrop natively — also removing ~30 lines of duplicated modal markup.
- **`WritingEngine.tsx`:** writing task tabs now carry `aria-current="true"` on the active tab (previously CSS-class-only) and the tab list has `aria-label="Writing tasks"`.
- **`ResizableSplitScreen.tsx`:** the resize divider (`role="separator"`, already had solid `aria-orientation`/`aria-valuenow`/keyboard support) now has `aria-label="Resize passage/question panes"` — previously announced only as an unlabeled "separator."
- **`AudioRecorder.tsx`:** added a discrete `role="status"` announcement for recording start/stop (keyed by `status`, not the per-second elapsed counter) — recording auto-starts, so a screen reader user not already focused on the widget previously had no way to know it had begun.
- **`RestrictedAudioPlayer.tsx`:** added `aria-label="Listening test audio"` to the (deliberately controls-less) `<audio>` element.
- **Verified via calculation, not assumption:** `text-gray-500` on white = 4.84:1 (passes AA, resolves an open `DESIGN_SYSTEM.md` question); `text-danger-700` on `bg-danger-50` (the Badge component) = 5.52:1 (passes); `placeholder:text-gray-400` on white = 2.54:1 (fails — documented as a recommendation, not fixed blind, since every field already has a proper label so no information depends on the placeholder's contrast).
- **Investigated, no defect found:** admin CMS form label association (uses the valid "wrapping label" pattern throughout, not `htmlFor` — verified consistent, not a false negative from the initial `htmlFor` grep); no toast/snackbar system exists anywhere (all feedback is inline `role="alert"`/`role="status"`, already accessible by default).
- `ACCESSIBILITY_REPORT.md` (new).

### Fixed — M4.2: Performance Optimization (see PERFORMANCE_REPORT.md for full detail)
- **`components/test-engine/TestEngine.tsx`:** the most impactful fix of this pass. `TestEngine` was reactively subscribing to `answers`/`flagged`/`timeSpentPerQuestion`/`remainingSeconds` at its top level purely for use inside `handleSubmit`'s closure (never read in JSX) — meaning the entire question sheet re-rendered on every keystroke anywhere in the module and every second from the countdown timer, for the whole duration of every timed exam. Fixed at the root (`handleSubmit` now reads `useTestStore.getState()` at call-time instead of subscribing reactively) plus defense-in-depth (`ReadingPassagePane`/`ListeningAudioPane`/`QuestionSheetPane` wrapped in `React.memo`).
- **`app/admin/attempts/page.tsx`:** was hard-capped at `take: 50` with no pagination, silently hiding anything past the 50 most recent attempts — now uses the same `parsePagination` pattern as `/admin/tests`/`/admin/users`.
- **`app/page.tsx` + `components/layout/NavbarAsync.tsx` (new):** the marketing homepage `await`ed a DB-backed auth check before rendering anything, including fully-static content with no data dependency. Split into a streamed `<Suspense>` boundary so the static shell paints immediately; documented trade-off (a logged-in visitor may briefly see the signed-out navbar).
- `PERFORMANCE_REPORT.md` (new) — full audit: 3 fixes, 4 "investigated, already good" findings (Server Components ratio, N+1 queries, font loading, Recharts code splitting), and 5 documented-not-fixed items with reasoning (admin image `next/image` conversion, `BandProgressChart` streaming, admin/analytics streaming, Sentry bundle cost, experimental PPR).

### Added — M4.1: Monitoring & Observability
- **Sentry** (`@sentry/nextjs`): `sentry.server.config.ts`/`sentry.edge.config.ts`/`sentry.client.config.ts`, `instrumentation.ts` (`register()` + `onRequestError`), `next.config.js` wrapped with `withSentryConfig`. Safe without a live DSN — `Sentry.init()` no-ops rather than throwing; verified via a full `next build`. `handleApiError.ts` reports genuinely unexpected errors (the generic `instanceof Error` fallback) to Sentry; expected client errors (401/422/429/409) are logged but never reported, to avoid alert fatigue on non-bugs.
- **Structured logging** (`lib/logger.ts`, Pino): JSON in production, pretty-printed in development, built-in `redact` for secret-shaped keys as a safety net.
- **Request IDs for every request** (`middleware.ts` + `lib/observability/requestId.ts`): generated once per request (or forwarded if the client sent one), set on both the outgoing request (readable via `next/headers` from any Route Handler/Server Component without threading the request object through call signatures) and the response header (`x-request-id`) for client-side/support correlation. Verified live: unique ID per request, present on real responses.
- **Health endpoints:** `GET /api/health` (liveness — no dependencies, so a slow DB can't make an orchestrator kill a live instance) and `GET /api/health/ready` (readiness — a real `SELECT 1` against Postgres; the one deliberate, safe exception to this codebase's "no raw queries" rule, since it's a static string with zero user input). **Caught and fixed during verification:** both were being statically prerendered by Next.js (frozen at build time) until `export const dynamic = "force-dynamic"` was added — confirmed via `next build`'s route table before/after. Smoke-tested against a real running server: `/api/health/ready` returned a genuine successful round-trip to the live Supabase database.
- `app/global-error.tsx` (new) — catches errors in the root layout itself (`app/error.tsx`'s boundary sits inside the root layout and can't reach failures there); both boundaries now report to Sentry.
- New env vars: `SENTRY_DSN`, `NEXT_PUBLIC_SENTRY_DSN`, `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_AUTH_TOKEN`, `LOG_LEVEL` — all optional, all fail safe without values set.

## 2026-08-02

### Fixed
- **Critical:** `POST /api/test-attempts/:attemptId/submit` (Listening/Reading auto-grading) had no authentication or ownership check — any request could submit/overwrite another student's scores. Added `requireUser()` + ownership + in-progress guards matching the sibling `writing-submit`/`speaking-upload` routes. (`app/api/test-attempts/[attemptId]/submit/route.ts`)
- **Critical:** The full answer key (`Question.correctAnswer`) was serialized into the module page's client props before a candidate submitted, defeatable via View Source/DevTools. Introduced a server/client type boundary (`ClientGradableModule`/`ClientQuestion` in `types/test.ts`, stripped via new `lib/mappers/toClientModule.ts`) so the test-taking UI never receives answer keys pre-submission. (`types/test.ts`, `lib/mappers/toClientModule.ts`, `app/test/attempts/[attemptId]/modules/[moduleId]/page.tsx`, `components/test-engine/{TestEngineClientWrapper,TestEngine,QuestionRenderer}.tsx`, `lib/store/testStore.ts`)
- **Critical:** `TestAttempt.status` never transitioned to `SUBMITTED` anywhere — every module-submit path only upserted a `ModuleAttempt`, so a candidate could never reach their own results page (`/dashboard/attempts/[attemptId]` 404s unless `status === "SUBMITTED"`) no matter how many modules they finished. Added `lib/scoring/finalizeAttemptIfComplete.ts`, called from all three submit routes' transactions. (`lib/scoring/finalizeAttemptIfComplete.ts`, `app/api/test-attempts/[attemptId]/{submit,writing-submit,speaking-upload}/route.ts`)
